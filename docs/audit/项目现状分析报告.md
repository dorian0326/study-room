## 2. 需求与业务认识

### 2.1 背景、目标与角色

SRS v3.0标题为《智能自习室管理预约系统》，版本日期2026-11-01。项目旨在减少占座不到场与纠纷，提高座位有效利用率、管理效率及分配公平性，并提供资源决策统计。G-01～G-04成功指标仍缺实际量化依据，不能以完成界面代替效果证明。

角色为普通用户（学生与教师合并）、管理员、运维。普通用户操作本人预约/违规/申诉；管理员管全部设施、规则、用户和违规、报表；运维读系统日志、脱敏门禁及备份监控。管理员可读审计日志，但不能因此读取门禁明细；后端角色矩阵见`app/permissions.py`，对象归属由各路由的user_id条件处理。

### 2.2 范围与业务链

保留范围：账号与三角色、空间座位与开放日历、查询预约及冲突/幂等、扫码签到/手输编号替代、暂离返回、主动结束/超时释放、违规累计与阶梯禁约、申诉、站内通知、历史查询、设施配置、统计与运维。候补已由HD-41移出；教师专属优先、黑名单、频繁取消限制、维护补偿不在当前批准范围。统一身份认证为非目标，门禁对接由HD-16单独纳入，不能混为同一外部接口。

核心链为：注册登录 → 查询当天/目标时段可用座位 → 指定座位或区域自动分配 → 创建预约 → 换座/取消或窗口内签到 → 暂离/门禁返回/主动结束 → 自动违规与限制 → 本人申诉/管理员复核 → 历史通知与报表。管理员维护/关闭资源会影响预约，是跨模块关键链。

SRS有5个详细用例UC-007/009/010/102/104，以及注册、查询、修改、结束、历史、配置、报表等摘要用例。共享依赖包括开放时间、有效预约排他、对象归属、服务端时间与通知留痕；用例图外链缺失，无法核实图上的include/extend关系，不自行补写。

### 2.3 关键规则与非功能要求

正文明确规则包括：签到±15分钟（含端点）；开始前≤15分钟允许取消但记违规；暂离保留30分钟，入馆记录判返；违规固定两周归档、不删除、不扣计数；满3/5/7…次分别禁约1/2/3…天；未签退每2次折算1次；管理员设施取消不计用户违规且无补偿。原文中取消、结束延迟、状态数等存在残留矛盾，见[问题清单](文档缺失与问题清单.md)。
