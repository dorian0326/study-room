## 1. 推进边界

本轮完成第一阶段五份文档并汇报，在进入代码修复前不改业务实现。后续按用户五阶段顺序推进；阶段内按课程要求滚动细化接口和测试，而不是先把全部代码改完再补证据。课程学生指引要求“小任务计划→学生核对批准→AI实现→另一成员审查→阶段验收”；尚未明确的规则不由AI决定。

本轮只列候选任务，不建立“已批准/已完成”任务卡，不填虚构人员或Git提交号。用户已授权开展后续文档和核查；需要业务取舍的AUD-Q仍须明确真实决定，不能把这一总体授权当作每项业务冲突的答案。

## 4. 第四阶段：真实软件测试

### 4.1 方法、环境与数据

保留pytest+FastAPI TestClient；使用Alembic从零建每用例独立文件型SQLite，开启与生产相同外键/WAL/锁等待；后台调度关闭，测试显式触发扫尾并冻结时间。数据只用合成账号/预约，备份和恢复路径也放临时目录。真实并发采用多连接文件库；200并发HTTP性能须独立服务器和独立测试身份，不能把服务函数100线程视作200在线用户。

为CI至少在Python3.11/Node20运行一次；本机3.13/22作为额外兼容环境，依赖版本记录可复现。前端lint/build只证明静态检查与打包，另需实际浏览器主链、空状态、断网/重复提交、角色菜单/直接URL、移动390px/真实手机摄像头、BarcodeDetector不可用和媒体访问。禁止对README公共演示站压测或清库。

### 4.2 用例与证据

| 类别 | 必测内容 | 依据/记录 |
|---|---|---|
| 正常功能 | 注册登录、查询筛选/区域分配、创建换座取消、扫码暂离结束、历史通知、管理报表 | 关联每个FR/UC/BR，列前置角色/数据、输入步骤、输出及数据库后置 |
| 边界与异常 | ±15分钟含端点、30分钟、预约结束、跨日/时区、空白/长度/非法枚举、重复键不同负载、写锁/DB异常 | 预期来自经核验规则；冲突项先待确认，不以当前实现当真值 |
| 权限隐私 | 未登录401、角色403、双用户对象404、运维不预约/申诉、管理员不读门禁、公开字段不泄漏身份 | 同时检查返回字段、DB不变和审计记录 |
| 事务并发 | 100连接抢座、同键16重试、维护vs预约、审核并发、取消/签到/扫尾竞争、换座失败回滚 | 保存线程数/连接/同步屏障/成功冲突数/最终DB状态；失败如实保留 |

| 运维质量 | 备份恢复逐笔对账、过期清理、外部延迟降级、P95/200并发/零超售、可信NTP、月度可用率 | 未有长期证据的继续待测；保持SRS阈值，不能跑完挑有利指标 |

正式TC至少包含：测试编号、关联需求/规则/Q/ADR、层级、风险、前置数据角色、输入步骤、预期输出与DB不变量、预期人工确认人、实际结果、状态、命令/环境/代码版本/证据路径。通过/失败/未执行/阻塞分开统计，不虚构覆盖率。

测试报告包含目的、范围、环境工具、方法、用例、实际执行通过/失败/阻塞数、缺陷和修复、回归、真实覆盖（若有采集）、结论与残余问题。每次执行保存完整输出和退出码，摘要须能从原始数据重算。测试预期不正确时保留修改依据与人工批准，不能删断言求全绿。

### 4.3 完成标准

确认范围内的每项需求至少有可执行用例或明确限制及批准依据；核心业务链正常/异常/权限/数据后置通过，严重缺陷无遗漏，受影响回归通过，当前阶段diff经另一成员审查，阶段验收人真实签认。NFR未证实仍待测，不能据此宣布全部通过。

## 5. 第五阶段：整理与提交

按[老师要求清单](老师任务要求清单.md)汇总五类最小包，复用根SRS和一份接口关键设计；数据库/详细设计必要时拆附录，由入口指向唯一维护源。所有文档具备标题、目录、版本与状态，术语/编号/路径/API和代码一致，图可渲染，源文件及引用齐全。

最终检查表逐条关联TR-01～21及需求矩阵，列完成/待核验/阻塞/获准排除、证据、责任人；保留真实人工审查、阶段验收、AI纠错（如确实发生，记录其错误→证据→修正→人工复核，不编故事）。只选关键证据，避免提交大批临时数据库、依赖、凭据、无关聊天截图或伪造提交号。提交格式、截止时间、报告A/B是否需要随本次补交，按后续实际任务书确认，当前不擅自宣称老师硬性要求。

## 6. 近期可执行顺序与自检

1. 汇报本轮五份审计材料和实际测试结果；保留原文件、原始失败和未决问题。
2. 下一阶段先补基线入口、事实架构讨论稿和Q/ADR候选，查原FR/HD/图/历史证据能否回收；不依赖这些的只读接口和ER结构可先写。
3. 优先由项目组确认并发机制、门禁范围、P-024、预约候选参数、恢复目标；分配真实责任人及复核人。
4. 对获准的小任务冻结接口和人工预期，再按S1～S6逐链修复、回归、审查；不一次重构系统。

第一阶段自检：五份指定文档齐全；代码、原SRS与业务库未改；实现状态有路径与实际/待验证区分；老师最小包未被误写成已完成；不签署任何人工确认或阶段验收。
