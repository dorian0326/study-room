## 阶段准入约定

开始一个具体任务前，负责人和交叉审查人应确认：关联 Q 已关闭或明确为非阻塞、相关 ADR 状态清楚、提供方和调用方认可接口字段/状态/错误语义、测试预期已由业务责任人核对、环境与密钥配置明确、任务卡包含负责人/审查人/范围/完成条件。

目前仓库没有已填写的阶段准入或验收记录，因此本计划本身不批准开始某个阶段，也不宣布任何阶段完成。

建议运行命令：

- 完整检查：python scripts/dev.py test
- 单项后端测试：在 backend 环境运行 python -m pytest -q tests/test_assigned_workflows.py
- 前端单项检查：在 frontend 环境运行 npm run lint、npm run format:check 和 npm run build

将实际执行环境、代码提交、命令、原始结果和失败处理记录到 docs/evidence/；不要把未执行的案例标为通过。

## 任务卡使用

新增任务复制 [任务卡模板](./tasks/任务卡模板.md)，关联一个明确 Issue、当前基线提交、需求、ADR、接口及测试。若实现中需要修改业务规则、接口契约、数据库迁移或引入新依赖，先暂停受影响任务并重开相应 Q/ADR。
