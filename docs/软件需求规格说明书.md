# 第一部分 项目概述

## 1.1 问题陈述

高校自习室座位资源在考试周等时段高度紧张，"占座不到场"现象普遍：部分学生以书本、水杯等物品长时间占用座位却不到场学习，导致座位资源被闲置浪费；而真正需要座位的学生在馆内寻找不到空位。现有管理方式依赖人工巡查，存在三方面困难：发现难（管理员无法持续巡视全部座位）、判定难（"离开"与"占座"缺乏客观标准）、处置难（劝阻缺乏依据，易引发纠纷）。

## 1.2 业务目标

| 编号 | 业务目标 | 说明 | 成功指标 | 指标依据 | 优先级 |
|---|---|---|---|---|---|
| G-01 | 提升座位有效利用率 | 通过"预约+签到"机制，使座位在预约时段内实际有人使用 | 预约签到率、座位有效使用率 | ⚠️ 待确认 | 高 |
| G-02 | 减少占座纠纷 | 以系统规则自动判定未到场与超时占用，规则透明可追溯 | 因占座产生的管理纠纷数量 | ⚠️ 待确认 | 高 |
| G-03 | 降低管理人力成本 | 自动化签到判定与违规记录，替代人工巡查记账 | 管理员人工巡查工作量 | ⚠️ 待确认 | 中 |
| G-04 | 保障座位分配公平 | 先到先得 + 临时取消限制（候补机制已移出本期范围 — HD-41） | 用户对分配公平性的满意度 | ⚠️ 待确认 | 中 |
| G-05 | 支撑资源调配决策 | 输出座位利用率与时段高峰统计 | 可用统计报表项 | 交付可查询报表即可 | 低 |

## 2.4 详细用例

### UC-007 预约座位

| 元素 | 内容 |
|---|---|
| **用例编号与名称** | UC-007 预约座位 |
| **参与者** | 主要：用户（HD-14）用户；次要：座位并发控制机制（系统内部） |
| **触发事件** | 用户在座位选择界面点击「确认预约」 |
| **前置条件** | ① 用户已登录且账户状态为「正常」；② 所选座位状态为「可用」；③ 预约时段完整落在自习室开放时间内；④ 用户当前有效预约数未达上限 |
| **主流程** | 1. 用户选择自习室、日期；2. 系统展示座位布局图与各时段可用状态；3. 用户选择目标座位与时段；4. 系统校验时段是否在开放时间内（BR-001）；5. 系统校验用户有效预约数量上限（BR-004）；6. 系统校验用户是否处于违规限制期（BR-090~099）；7. 系统校验座位状态与时段冲突（BR-010/BR-011/BR-013）；8. 系统以乐观锁机制写入预约记录（BR-051）；9. 预约创建成功，状态置为「已预约」，座位对应时段锁定；10. 系统发送预约确认通知（FR-050） |
| **替代流程** | A1 时段超出开放时间 → 提示可选时段，返回步骤 3；A2 用户已达预约上限 → 拒绝并提示上限规则（BR-004）；A3 用户处于违规限制期 → 拒绝并告知限制解除时间（BR-090~099）；A4 座位已被他人预约 → 提示并提供「加入候补」入口（BR-080） |
| **异常流程** | E1 乐观锁版本冲突（并发抢同一座位）→ 系统拒绝写入，返回「该座位刚被他人预约」提示，建议重试或选择其他座位（BR-051）；E2 网络中断导致重复提交 → 系统按幂等键去重，仅创建一条预约（BR-052）；E3 数据库写入失败 → 事务回滚，不产生残留锁定，提示用户重试 |
| **成功结果** | 生成一条状态为「已预约」的预约记录；该座位在该时段由「可用」转为「已预约」；用户收到确认通知 |
| **失败结果** | 不产生任何预约记录；座位状态保持不变；用户收到明确失败原因与可选后续动作（改选/重试） |
| **关联规则** | BR-001、BR-004、BR-010、BR-011、BR-013、BR-090~099、BR-050、BR-051、BR-052 |
| **验收标准** | ① 100 个请求并发抢同一座位同一时段，系统最终仅有 1 条预约成功，其余返回明确冲突提示，超售次数为 0；② 任意冲突场景下不产生"半锁定"残留；③ 预约成功后座位状态与预约记录一致 |
| **使用频率/触发规律** | 高度集中于考试周与每日开放前时段；具体日均预约量 ⚠️ 待确认（需业务方提供历史数据，不作为设计假设） |

| **成功结果** | 预约状态变为「已取消」；座位时段释放并可被再次预约；候补机制已移出本期范围（HD-41），不再产生候补转正 |

| **关联规则** | BR-030、BR-031、BR-032、BR-033、BR-034、BR-082、BR-083 |
| **验收标准** | ① 禁止窗口内取消被拒绝且提示准确；② 窗口外取消成功且座位立即可被预约；③ 取消本身不产生候补转正（候补已移出 — HD-41）；④ 取消后不触发违规二（HD-27） |

```

   ↓

```

### 5.1.4 违规治理业务过程

```
违规事件发生（三类：①离开图书馆未点「临时离开」②预约后15分钟未到达 ③时段结束未签退）
   ↓
系统生成违规记录（含证据引用；违规一依赖图书馆人脸/门禁记录）
   ↓
在 2 周统计周期内累计违规警告数（违规三：每 2 次警告折算 1 次违规警告）
   ↓
按处罚阶梯判定（无上限）：满 3 次 → 禁止预约 1 天；满 5 次 → 2 天；满 7 次 → 3 天……依次递增
   ↓
触发处罚后：警告记录保留、**次数不扣除不清零**，继续累计至窗口到期后统一清零归档（HD-19）
   ↓
通知用户（违规类型 + 发生时间 + 累计警告数 + 申诉途径）
   ↓
[用户提交申诉] → 管理员复核 → 维持 / 撤销 / 降级
   ↓
统计周期期满 → 违规记录清零并归档（不删除，不再参与累计）
```
