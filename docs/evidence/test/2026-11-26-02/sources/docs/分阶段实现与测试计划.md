### 4.2 环境和数据控制

本轮实际环境为Windows、Python 3.13.5隔离venv、Node 22.18.0、npm 10.9.3。后端按依赖声明安装，前端按package-lock执行npm ci；完整版本见证据环境日志。CI声明Python 3.11和Node 20，最终还应在相同版本核对，不将本地结果直接写成CI通过。

测试使用既有合成用户和固定时钟、临时文件SQLite；关闭后台自动扫描/备份/日志清理，由场景显式调用相关用例。复制到隔离目录运行，避免开发数据库和已有业务数据受影响。HTTP证据脱敏凭证，Mock响应和真实TestClient响应分别标注。

未来复测固定代码版本、数据库迁移、参数与时区。密码、会话、重置码、真实门禁标识不写入报告；对数据有破坏性的恢复或故障注入只在隔离库执行。

## 6. 阶段准入、Issue执行与审查

### 6.1 准入检查

每次开始受影响模块任务前，由负责人、调用方及复核人检查：

- 关联需求/HD/ADR及接口版本可定位，阻塞问题已有结论或明确限定影响。
- 输入、输出、错误、副作用、状态、本人范围、幂等和事务语义明确。
- 测试预期与合成数据独立核对，未从缺陷实现倒推预期。
- 环境、时区、密钥、迁移及运行方式可复现。
- 对应Issue、允许修改范围、复核人、完成条件和停止条件明确。

当前可继续阅读与设计、隔离准备、无规则争议的复测和文档工作；涉及需求修订、架构/契约改变或业务代码修正时按既有授权与变更流程处理。本文不伪造准入批准人或批准日期。

| 关联 | FR/BR、原Q/ADR、DISC/GAP、API、TC-LOCAL/TC-IF及对应自动化 |
| 允许修改 | 该业务模块、必要测试与关联文档，具体文件按任务确认 |
| 禁止修改 | 未批准规则、范围外模块、验收预期、依赖技术栈及运行业务数据 |
| 依赖与不变量 | 前阶段能力、权限、区间排他、状态转换、通知与事务边界 |
| 完成标准 | 代码或文档变更、适用回归、真实输出、另一成员审查及同步依据 |
| 停止条件 | 发现需改需求/共享契约/迁移/依赖时反馈受影响范围，不自行扩张 |
| 状态 | Issue关闭状态与本轮“待核验/待审查/需修改/已验证”分开记录 |

### 6.3 审查与测试记录要求

模板H记录的任务/提交、实现者/审查者、需求与契约、权限事务并发幂等、命令环境结果、未执行阻塞、发现处理和文档同步，均根据实际参与与输出填写。没有人工复核时结论为“待审查”，不能把工具执行者填成已签字的成员。

对测试失败先判定是实现、用例预期还是需求冲突；实现错误修实现，预期修改需独立依据和实际确认，需求冲突重开原问题。变更后保存新增日志，旧失败证据不覆盖删除，适用回归通过后再更新状态。

## 7. 阶段验收与最终交付

### 7.1 每阶段验收动作

由模块负责人演示完整主链，另一成员抽测关键异常；张东岩核对自动化环境、版本与原始结果，周俊博核对需求/接口和未决事项，相关成员核对数据状态与审计。结果以模板I据实记录。

| 阶段 | 主链演示重点 | 最小异常抽测 | 验收资料 | 当前验收结论 |
|---|---|---|---|---|
| S0 | 登录→权限→注销，迁移后健康 | 失效会话、非管理员操作、自降权 | 迁移/认证/权限结果与实际交叉审查 | 待成员验收 |
| S1 | 搜索→创建→换座/取消→历史通知 | 同座竞争、同键异载荷、失败保留原座 | 预约回归、并发对账及差异处置 | 自动化证据已有，阶段待验收 |
| S2 | 签到→暂离→有效返回/超时→结束 | 截止整秒、无门禁返回、迟到事件 | 状态边界、外部接入范围与演示记录 | 模拟链证据已有，差异未闭合 |
| S3 | 违规累计→禁约→申诉→审核通知 | 第3次不同入口、多限制及通知失败 | 周期/阶梯/审核/补偿与审计对账 | 现有断言通过，业务闭环待验收 |
| S4 | 维护→取消通知→报表→日志→恢复 | 导入非法行、历史统计、恢复核对 | 管理运维结果、口径及恢复记录 | 自动化部分已有，质量边界保留 |
| S5 | 干净环境完整三角色链 | 设备/外部故障、越权、获准负载 | 发布版本、环境、系统/质量结果、真实验收人和日期 | 未执行综合验收 |

每张验收单包括：阶段/版本/环境、完成与未完成需求、演示及异常、自动/人工证据、Q/ADR/接口变更、残余风险及下阶段阻塞、结论/真实验收人/日期。没有执行的内容保持未执行或待核验，不倒填日期。

### 7.2 交付与退出条件

1. 需求、架构、接口、阶段和Issue引用一致；所有重大差异有处置，未完成内容明示。
2. 对应自动化及受影响回归通过，失败有真实处理记录；不把测试数等同覆盖率。
3. 并发、权限、异常、维护、违规、通知与恢复关键不变量有适当层级证据。
4. 实际交叉审查与阶段演示完成；自动化通过与人工验收分别记录。
5. 从干净环境按说明启动，配置/密钥/迁移/备份方式明确，真实外部与模拟范围清晰。
6. 质量目标如未满足，必须有整改或正式范围/验收口径决定，不能在计划中自动降低指标。
